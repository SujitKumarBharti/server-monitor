Server Monitor - Project Introduction and Complete Flow

Server Monitor is a PHP-based uptime and internet monitoring application. Apache serves the browser dashboard, while systemd runs the continuous background monitor.

1. Complete Runtime Flow

Browser request
    -> Apache
    -> index.php
    -> includes/database.php
    -> MySQL/MariaDB
    -> dashboard response

Server boot
    -> systemd
    -> servercheck.service
    -> scripts/server_check_daemon.php
    -> ping / DNS socket check
    -> includes/logger.php
    -> database + logs + status files
    -> includes/mailer.php
    -> SMTP server

2. What the Project Does

  • Apache serves index.php as a dashboard.
  • systemd runs the long-running PHP daemon.
  • Internet status is checked with ping and a DNS socket fallback.
  • MySQL/MariaDB stores uptime and status statistics.
  • Logs and current status are written to the application logs directory.
  • SMTP sends alerts and daily summary emails.

3. Source Tree and Responsibility

project/
  index.php                         Browser dashboard and manual actions
  includes/database.php             MySQL/MariaDB connection and queries
  includes/logger.php               Database updates and file logging
  includes/mailer.php               Direct SMTP client and email reports
  scripts/server_check.php          One-time connectivity check
  scripts/server_check_daemon.php   Long-running systemd process
  scripts/daily_summary.php         Manual daily summary command
  scripts/uptime_updater.php        Uptime update command
  config/database.json              Database credentials; sensitive
  config/smtp.json                  SMTP credentials; sensitive
  config/sendmail.json              Recipient and message settings
  logs/                             Generated logs and status files

4. Dashboard Flow

  1. Browser requests index.php through Apache.
  2. index.php loads includes/database.php.
  3. The database class reads config/database.json.
  4. mysqli opens the MySQL/MariaDB connection.
  5. Today's row and the last 30 days of history are loaded.
  6. logs/last_status.json supplies the latest live status.
  7. Uptime percentages are calculated and rendered.
  8. Manual email actions use the mailer and JSON configuration.

The dashboard does not run the continuous monitoring loop; systemd does.

5. Monitoring Daemon Flow

servercheck.service starts /usr/bin/php scripts/server_check_daemon.php as www-data.

  1. Loads logger and mailer.
  2. Creates missing log directories.
  3. Sends a startup notification.
  4. Checks internet connectivity.
  5. Saves state in logs/last_status.json.
  6. Detects status changes and updates database counters.
  7. Runs the uptime updater approximately every minute.
  8. Sends the previous day's summary around midnight, with catch-up logic.
  9. Repeats while systemd keeps the process alive.

6. Data Flow

Database

includes/database.php uses prepared mysqli statements against servercheck.server. It stores uptime, offline time, reboot, shutdown, and internet-offline counters.

Files

  • logs/last_status.json: latest status.
  • logs/last_summary_date.txt: last summary date.
  • logs/service.log: daemon activity.
  • logs/YYYY-MM-DD/server.log: daily events.

Email

includes/mailer.php opens an SMTP socket, authenticates with TLS or SSL, and sends startup, status, daily summary, and manual dashboard emails.

7. Deployment Flow

  1. Install Apache, PHP, mysqli, MariaDB/MySQL, ping, and iproute2.
  2. Clone to /var/www/html/project/servercheck.
  3. Create the database, user, and server table.
  4. Create server-only JSON files in config/.
  5. Make logs/ writable by www-data.
  6. Point Apache DocumentRoot to the project.
  7. Create /etc/systemd/system/servercheck.service.
  8. Run systemctl daemon-reload, enable, and start it.
  9. Check PHP, Apache, application, and journal logs.
  10. Open the dashboard and test email delivery.

Detailed commands are in How to deploy/README.md; package requirements are in Software Req/README.md.

8. What Runs Where

Apache web request:        /var/www/html/project/servercheck/index.php
PHP background process:    /var/www/html/project/servercheck/scripts/server_check_daemon.php
systemd unit:              /etc/systemd/system/servercheck.service
Apache site config:        /etc/apache2/sites-available/servercheck.conf
Database files:            /var/lib/mysql/
Application configuration: project/config/*.json
Application logs:          project/logs/
Service logs:              journalctl -u servercheck

9. Daily Operations

sudo systemctl status servercheck --no-pager
sudo systemctl is-active servercheck
sudo journalctl -u servercheck -f
sudo systemctl restart servercheck
sudo -u www-data php scripts/server_check.php
sudo -u www-data php scripts/daily_summary.php 2026-09-19

10. Security Rules

  • Never commit real JSON credentials.
  • Use a dedicated database user and SMTP app password.
  • Run the daemon as www-data, not root.
  • Give write permission to logs/ only.
  • Use HTTPS and restrict dashboard access.
  • Rotate credentials after exposure.
  • Back up the database separately from generated logs.
